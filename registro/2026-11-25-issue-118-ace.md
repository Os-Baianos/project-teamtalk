Quem: Ace (Acebmoon), com Claude

PR: ver PR da branch `feat/auth-supabase`

## O que foi feito
- Banco (projeto Supabase `project-teamtalk`): tabela `perfis` (nome e @ único, formato validado), RLS (leitura para logados, edição só do dono), perfil criado automaticamente no cadastro por gatilho e função `arroba_disponivel` para a tela de cadastro. Migração: `perfis_com_arroba_unico`.
- Front: cadastro, login e sair agora usam o Supabase Auth. Sessão por cookie via `@supabase/ssr`; middleware renova a sessão e protege as rotas.
- Erros do Supabase traduzidos para português (e-mail ou senha incorretos, e-mail já cadastrado, @ em uso etc.).
- Removida a conta de demonstração provisória.

## Arquivos criados ou alterados
- `DEV/front-end/src/supabase/` (ambiente, servidor, sessao-middleware)
- `DEV/front-end/src/sessao/acoes.ts` (entrarAction, cadastrarAction, sairAction) e `constantes.ts`

- `DEV/front-end/src/app/cadastro/*`, `src/design/telas/login.tsx`

## Novidades para quem vai usar
- É preciso criar `DEV/front-end/.env.local` com `NEXT_PUBLIC_SUPABASE_URL` e `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (modelo em `.env.example`). O arquivo não vai para o Git. Na Vercel, as mesmas duas variáveis.
- Dados do usuário logado: tabela `public.perfis` (colunas `id`, `nome`, `arroba`).
- Nenhum token, ícone ou componente visual novo.

## Pendências e dúvidas
- Se a confirmação de e-mail estiver ligada no Supabase (Authentication > Providers > Email), o cadastro não loga na hora. Para a A3, sugerimos desligar "Confirm email".
- Cadastro de ponta a ponta com e-mail real ainda não testado: o Supabase recusa e-mails de teste como example.com.
- Contatos (#120) é o próximo passo.
